Morning run

The morning run's steps

When Automation is on, the database's own clock (pg_cron) takes one step every few minutes inside your window: first your saved searches, then any addresses waiting for the verifier, then the next new candidates (until "New qualified subscribers to aim for per day" qualify today, reading at most "Candidates to read per day"), then drafts for the potential subscribers who are due (up to today's send cap, which grows while the domain warms up). Each step runs on a single-use ticket that opens only the engine's own doors. It never approves and never sends: every draft waits for you in the review queue. It stops for the day after three failed steps in a row.

Review queue

The drafting engine writes only from facts the database holds about that person, each sure enough on its own, in the source's own words; the database checks every draft before it appears here, and greets by first name only when the evidence establishes it. Approving sends nothing. Each card is the message exactly as it would go out, and what it says about the person with the evidence behind it. Approving several asks you to type how many, and the database approves exactly that many or none. An approved draft goes out only when you press Send — in test mode, only to your test inbox.

Sends

Every email handed to Resend, newest first. A send is written down before Resend is called, with one key per draft, so "Try again" can never send it twice; an answer still missing after 23 hours is marked failed rather than retried. Delivery, bounces and spam complaints arrive from Resend's signed webhook.

Discover and research

Saved searches and the daily budget

Providers

A provider is used when its key is set (Supabase → Edge Functions → Secrets) and it is switched on here. Apollo and Clay cost money per call, so they stay off until you switch them on. Whatever a provider says is weighed like any other source: an address it found is unverified until a verifier or you confirm it, and a title or employer it reports is never something an email may cite.

Addresses and enrichment

Recent runs

Finding someone makes them a candidate, not a prospect. Research reads their own pages (robots.txt respected) and records only what it can quote; the database checks every quote against the stored page and decides which pages are their own. Nothing here writes, approves or sends an email. Every search, page, Claude read and email lookup counts against the daily budget, which the database enforces.

Add a prospect

Finding someone again — any casing of their address, a profile link with tracking tags or a mobile host — adds to the same record. Names, confidences, scores and status are worked out by the database from the evidence: nothing typed here is taken as certain.

Suppressions

A suppression is permanent. It outlives any change to a prospect record, cancels every unsent draft for that address, and the database refuses any send to it.

Outbound settings

No secret is stored here; API keys live in the Edge Functions' secrets. Raising the daily cap or leaving test mode asks you to confirm, and every change is recorded in the activity log below.
