Publishing

Auto publish never publishes malformed, thin or incomplete research: an article is only eligible when every check below passes and kickoff is inside the lead-time window. Everything else is held as ready and the failing check is named on the row.

Articles

Records come from the committed store (articles/data/index.json) and, where this account can read it, the live publication table. Generating and refreshing an article is the research pipeline’s job — node tools/articles/generate.js — because it needs the football engine and two schedule feeds. What this screen changes is whether an article is published; the next pipeline run writes or removes the page.

How an article gets published

1. The research already exists — the terminal prices the game.
2. node tools/articles/generate.js reads that research through the same fbBriefGame() / fbNflBriefGame() the terminal calls, and writes a record. Nothing is re-modelled.
3. The record runs the publication checks. Passing them makes it ready; failing one keeps it a draft and names the check.
4. You preview it, then publish — or leave Auto publish on and it publishes itself once it is ready.
5. node tools/articles/build_articles.js writes the static page, the hubs and the sitemap. Published articles only.
6. Before kickoff the pipeline re-reads the research; a changed projection moves updated_at, an unchanged one moves nothing. After kickoff the record freezes.

Featured games

EdgeDesk prices every game on the board and writes about the ones worth a permanent research trail. A game is featured when its editorial priority clears the floor for its sport and it is inside that week’s cap — or when you feature it by hand, which outranks both. Every score below is itemised: open a row to see exactly what earned it, and where each input came from.

Running it

Score the slate npm run editorial:select — rank every game, apply the floor and the cap. Your FEATURE and UNFEATURE survive it.
Pregame npm run editorial:pregame — capture the immutable snapshot, write the article, run the quality gate.
Postgame npm run editorial:postgame — fetch the box score, audit every claim, grade result against process, store the lessons.
Everything, live npm run editorial:run · and publish what passes npm run editorial:publish
One game node tools/editorial/run.js postgame --game NFL:2026_01_NE_SEA --force --network
Regenerate an article — the same command with --force: it ignores the idempotency log for that game and rewrites the record in place. The URL never moves.
Preview before publishing npm run articles:preview then open /articles/_preview/<slug>/ (noindex, in no sitemap).
Or run the Editorial system workflow from GitHub Actions, which takes a phase, a game key and the publish switch as inputs.
