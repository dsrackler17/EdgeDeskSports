# 2026-10-26: eighteen failed runs, three root causes, one missing gate

## Summary

Between 12:03 and 12:54 UTC on 2026-10-26, GitHub Actions reported 18 failed
workflow runs across nine workflows. Each one sent its own email. They came
from **three** root causes. The process that let them reach `main` was **one**
missing gate: `main` has no branch protection, and four pull requests merged
while a check was red or had not yet reported.

The email subjects named an "implausible-EV guard" and a "board cache-token
case". Those are pull-request titles (the runs' display titles), not the
failing tests. Neither the guard nor the cache-token logic was what failed in
those runs.

`main` has been green since `74f0117bb` (#804, 12:59). The evidence below
comes from the job logs, which are quoted, and was reproduced locally in
worktrees at each failing SHA.

## What prevents a recurrence

| Failure mode | Now caught by |
|---|---|
| A file that no longer parses (JS, ES module, TypeScript, JSON, JSONL, inline `<script>`, shell, Python), or an unresolved conflict marker | `Core validation / Repository integrity` (`tools/ci/integrity.js`). It runs on every PR and every push to `main`, with no path filter, in about 20 s, and names the file and line. `tools/ci/integrity.test.js` drives it against synthetic repositories, starting with RC1's exact damage. |
| A workflow or script that runs a file or npm script that does not exist | the same gate (§6 of `integrity.js`) |
| A PR merged with its checks red or not yet reported | branch protection requiring `Repository integrity`, `Odds gateway suites` and `audit` ([BRANCH_PROTECTION.md](BRANCH_PROTECTION.md); needs the owner); `AGENTS.md` §5–§7 |
| "I ran the tests" without running the workflows the change starts | `npm run verify` / `verify:affected` read each workflow's own `paths:` and steps. On four of today's PRs, the workflows they predict match what GitHub actually started, exactly (34/34, 8/8, 3/3, 8/8). |
| An hourly board that contradicts its rules, unseen until an unrelated PR | `CFB published-board validation` runs the CFB validation and research-terminal suites on `main` after every Model Lab run |
| A browser suite that passes because Chromium failed to install | `continue-on-error` removed from the six Playwright install steps (collective ×2, games-sql, linemaker, nba, nhl) |
| Two sessions fixing the same failure | `AGENTS.md` §1 |
| Hand-merged generated artifacts or changelog entries | `AGENTS.md` §5 |

or after another test, reads as a regression in whoever's pull request
meets it first. Before today, #798, #794 and #793 each fixed one by hand.
