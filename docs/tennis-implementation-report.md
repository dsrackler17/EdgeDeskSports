## 5. Import reconciliation

### The bundle as supplied

The attached `EdgeDesk_Tennis_Claude_Dev_Bundle.zip` contains a **2,944-row
development sample**, not the 361,571-row archive. `CLAUDE_IMPORT_INSTRUCTIONS.json`
says so: *"Build and test against the sample; run the full historical import
outside the agent context."* The full `EdgeDesk_Tennis_Dataset_ATP_WTA_1968_2026.zip`
was not attached, so it has not been imported here.

| | rows read | accepted | rejected | skipped | reconciled |
|---|---:|---:|---:|---:|---|
| development sample | 2,944 | 2,944 | 0 | 0 | **yes** |
| second import of the same file | 2,944 | 2,944 | 0 | 0 | **yes — zero duplicates** |
| production-scale synthetic | 362,112 | 362,112 | 0 | 0 | **yes** |

The synthetic set exists to prove the system at real cardinality: 290,280
matches, 106,887 players, 715,245 feature rows. It is **not** the real archive
and no claim is made about its values — only about row counts, key
distributions, join fan-out and query plans.

### Coverage from the real sample

|---|---|

| players | 869 |

| surface unknown | 168 (5.7%) |

The supplied `validation_summary.csv` states the full archive is 199,389 ATP +
162,182 WTA = **361,571**, 1967-12-28 → 2026-05-25, surface known 98.5% / 96.98%,
weather covered since 2015 **0.42% / 0.67%**.

### Missing-data rates (development sample, after import)

| field | missing |
|---|---|
| surface | 5.7% |
| serve strength (first 150 service points of a career) | 30.3% of feature rows |
| return strength | 30.5% |
| strength of schedule (first 5 opponents) | 44.8% |
| mean feature completeness | **0.905** |

Every one is a named gap in `missing_fields`, never a zero.

### Weather coverage and limitations

Coverage is **very low by design and by source**: 36 observations for 2,944
matches. Three reasons, all stated on screen:

1. the archive's own weather enrichment covers under 1% of matches since 2015;
2. only **confidently resolved outdoor venues** are eligible;
3. **indoor events get an explicit `indoor` row**, not a null — weather does not
   apply rather than being absent.

And the limitation that governs all of it: the archive dates a match to its
**tournament week**, so every observation is a seven-day profile and
`temporal_precision = 'tournament_week'` says so. Nothing presents it as
conditions at first serve.

## 6. Model evaluation

Trained at production cardinality (290,280 matches), chronological splits:

```
train   201,276   1968-01-01 .. 2008-05-06
valid    43,131   2008-05-06 .. 2017-07-01
test     43,131   2017-07-01 .. 2026-12-30
```

| | n | log loss | Brier | accuracy |
|---|---:|---:|---:|---:|
| **EdgeDesk model** | 43,131 | **0.6047** | **0.2094** | **66.7%** |
| baseline: overall Elo | 43,131 | 0.6182 | 0.2150 | 65.4% |
| baseline: surface Elo | 43,131 | 0.6392 | 0.2249 | 62.6% |
| baseline: official ranking | 42,822 | 0.6273 | 0.2189 | 64.1% |
| baseline: market | — | **not possible** | | |

**Calibration ECE 0.0093** over all 43,131 test matches in all ten bins, none
too small to measure.

**Promotion gate: QUALIFIES — beats all three baselines, calibration passes.**
Registered as `tennis-baseline-1.0.0`, status `active`.

Broken down by tour, surface, level, best-of, favourite/underdog, confidence
bucket and season, each with its own n and a `small_sample` flag under 200.

**The model has not been shown to beat a market price.** No historical tennis
odds are captured, so the market baseline is impossible, and the build output
says so on every run rather than passing over it.

## 7. Security verification

free account, and as an entitled subscriber.

| check | result |
|---|---|
| unregistered source refused on `players` and `matches` | ✅ |

| archive registered `commercial_use = false`, research-only | ✅ |
| prediction cannot be updated or deleted, by anyone | ✅ |
| model version's evaluation and windows immutable | ✅ |
| published record immutable; settlement once only | ✅ |
| at most one active model per family | ✅ |
| `anon` reads the record, **denied** predictions/prices/opportunities | ✅ |
| `anon` **denied** features, staging, ingestion runs, data-quality issues | ✅ |
| signed-in **free** account reads **zero** priced rows | ✅ |
| entitled subscriber reads them; still **denied** the feature table | ✅ |
| no client role has INSERT/UPDATE/DELETE anywhere | ✅ |
| RLS on all 16 tables | ✅ |
| subscriber policies call the project's own entitlement rule | ✅ |
| all 10 exposed views `security_invoker = true` | ✅ |
| `anon` cannot reach `board_research`/`board_current`/`match_context` | ✅ |
| every definer function has a fixed `search_path`, none public-executable | ✅ |
| the live contract's own report still 16/16 `ok` | ✅ |

**Two real security-relevant findings, both fixed:**

1. **`set local role` in the SQL suite is scoped to one statement** under psql's
   autocommit, so every "anon cannot read this" assertion was passing as the
   table *owner*. Switched to session-level `set role`; assertions rose 28 → 75
   and several then genuinely failed until fixed.
2. **`record_health` read the private `ingestion_runs` table** as a
   `security_invoker` view granted to `anon`. It only ever passed because the
   tests used `count(*)`, which lets the planner skip the scalar subqueries; a
   real `select *` returned `permission denied`. Fixed with a narrow
   `tennis.ops_health()` definer function returning five aggregates and no rows,
   and the suite now does `select *`.

## 10. Remaining blockers

1. **The full 361,571-row archive was not supplied.** The bundle contains the
   2,944-row development sample and says the full import is run outside the
   agent context. The importer is built and proven against the same 108-column
   contract at 362,112-row cardinality; run `npm run tennis:record:import` with
   the real file.
2. **No live tennis or odds provider credentials.** Complete per the brief:
   provider interfaces, adapters, fixtures and the historical dataset all work;
   `licensed_feed.js` is isolated and imported by nothing.
3. **No historical market prices**, so the model cannot be compared to a price.
   Stated on every build.
4. **The archive is non-commercial.** The gate is real and the board says so.
   It must be replaced before it funds a paid tennis surface.
5. **`SB_DB_URL` must be set** as a repository secret before
   `tennis-record.yml` can run.

**One genuine failure this work caused, and fixed.**
`tools/games/builder.test.js` checks that every workflow references only
credentials the repository declares. The new `tennis-record.yml` referenced a
`SUPABASE_DB_URL` secret that did not exist in that registry — the test was
right to stop it. Rather than adding a secret, the workflow now uses the
repository's **existing `SB_DB_URL`**, which `deploy-intelligence.yml` already
uses to apply SQL migrations: the same kind of credential for the same kind of
use. It is passed to the tools under the name `SUPABASE_DB_URL`, which is what
Supabase's own documentation calls it. `builder.test.js` now passes 114/114,
and **no new repository secret is required.**
